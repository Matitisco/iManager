Revisión de rutas y servicios: operaciones/ventas, canjes, devoluciones/créditos, cuentas, señas, caja, comisiones y compras vía inventario/proveedores. Comisiones se calculan en backend; no se confía en una ganancia enviada por cliente. El precio unitario explícito conserva decimales de `total / cantidad` y puede diferir del precio descontado (regla existente); no se lo fuerza a igualar el total. La revisión no certifica todos los importadores ni reemplaza una política financiera aprobada. Pagos excedentes CREDIT/CHANGE son funciones legítimas y se conservan; redondeos residuales de conversión siguen la precisión monetaria existente.

Pruebas: `security-business-logic.integration.test.ts` agrega 43 regresiones (incluye Promise.all para stock, IMEI, claves, cobros y devoluciones/reintegros). Contra código original: 23 fallos de 38, más 5/5 fallos nuevos de subcentavos; después del fix: todas verdes. Tandas relacionadas de 104, 101 y 111 integraciones, 58 unitarias relacionadas y TypeScript frontend/backend aprobados. También HTTP real en loopback con `1e999`; no se guardan tokens. Una corrida se interrumpió por inodos compartidos y pasó al repetir después de liberar solo dependencias de este worktree.

Compatibilidad CI: se conserva ruido decimal menor a 1e-8; `edit-sale-seller` sigue verde sin modificarlo. Se actualizó la expectativa insegura de cuatro casos de `qa-hunt-purchases`: #717 ya impide anular reclamos compensados (409), antes esperaban 204. No se modifica ese resguardo ni su comportamiento.

Pruebas reproducibles: desde `backend`, configurar DATABASE_URL a una base **local exclusiva**, aplicar el schema existente con `prisma db push --skip-generate`, ejecutar `npm run test:integration -- src/test/security-business-logic.integration.test.ts` (un worker), y `npm run test:unit -- src/lib/money-input.test.ts --maxWorkers=2`. El helper de integración trunca esa base: nunca usar una URL compartida o remota.
