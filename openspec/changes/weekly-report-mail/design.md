# Diseño

Transporte HTTP prioritario con RESEND_API_KEY: POST https://api.resend.com/emails, Bearer, remitente SMTP_FROM o MAIL_FROM, Idempotency-Key existente y timeout de 15 segundos incluyendo lectura de respuesta. Devolver id para providerId; sin clave conservar nodemailer. Los errores del proveedor pasan al error de dominio 502 de la prueba. En frontend, separar prueba y guardado explícito, cancelar cargas al desmontar y ofrecer reintento si falla la carga; el timeout de la prueba debe dejar margen al timeout del proveedor. Tests con fetch simulado, sin correos reales.
Reusar resumen periódico y ganancia neta; sumar canjes confirmados, stock y deuda al preparar el envío. Congelar HTML/texto por tienda+período+destinatario. Reclamar cada entrega con transición atómica antes de SMTP; errores ambiguos no se reenvían automáticamente. Message-ID estable y Resend-Idempotency-Key. Timer de la API cada cinco minutos, solo con REPORT_MAIL_ENABLED=true, usando runDueReportsLocked igual que el comando manual. Arranca con onReady, cancela el intervalo y espera la ejecución activa en onClose; no superpone corridas locales. Cierre por SIGINT/SIGTERM. El CLI queda como alternativa puntual. Contar InventoryItem sin archivar con status EN_REVISION (motivos en batteryNote), sin restringir por fecha; HTML/texto incluyen sección y enlace #/stock/equipos?status=EN_REVISION. Inventario aplica ese filtro al abrir o cambiar el hash y limpia filtros anteriores. UI propia en Resumen periódico, con dock móvil y acceso desde Configuración. Prueba solo OWNER con límite persistente por tienda. QA exclusivamente en Postgres local y SMTP falso.
